## One law, one number

Every system in this essay obeys the same second-order law. Pull it, release it, and
the response is characterised entirely by the <b data-bind="zeta" data-fig="osc">0.12</b>
you see typeset here — the <Marginal note="The Q factor is 1/(2ζ) — radio people and mechanics people arguing about the same number.">damping ratio $\zeta$</Marginal> — and a natural frequency
$\omega =$ <b data-bind="omega" data-fig="osc">2.40</b>:

$$
\ddot{x} + 2\htmlClass{vbind vbind-osc-zeta}{\zeta}\htmlClass{vbind vbind-osc-omega}{\omega}\,\dot{x} + \htmlClass{vbind vbind-osc-omega}{\omega}^2 x = 0
$$

The numbers above are not decoration: they are bound to the figure. Grab the dot
riding the first overshoot and drag it — down to damp the ring, sideways to slow the
clock. The values in the prose answer[^2].

## Reading the response

Underdamped systems ring; overdamped systems creep home. The boundary — critical
damping — is where engineers usually want to live: fastest settling, no overshoot.
Drag the handle to the floor and watch the ringing die.

## Computing it

The snippet is an editor, not a picture. Click into it — vim bindings are on —
change the step count or the damping, and run it. Compilation happens in a worker
with a vendored clang and lld; the first run pays the toolchain cost once, then it
is cached hard. The program reads stdin for real.

<Code lang="c" runnable stdin code={`#include <stdio.h>

int main(void) {
    int steps;
    if (scanf("%d", &steps) != 1) steps = 100;
    double x = 1.0, v = 0.0, dt = 0.05;
    for (int i = 0; i < steps; i++) {
        v -= (2 * 0.12 * v + x) * dt;
        x += v * dt;
    }
    printf("after %d steps: x = %f\\n", steps, x);
    return 0;
}`} />

## One law, five runtimes

The same integrator, spoken natively everywhere the page can execute it. C++ goes
through the same clang worker with the C++ front end — and reads stdin too (type a
damping ratio first, then run):

<Code lang="cpp" runnable stdin code={`#include <array>
#include <cstdio>

template <int Steps>
auto simulate(double zeta, double omega) {
    std::array<double, Steps> xs{};
    double x = 1.0, v = 0.0;
    for (auto& out : xs) {
        v -= (2 * zeta * omega * v + omega * omega * x) * 0.01;
        out = x += v * 0.01;
    }
    return xs;
}

int main() {
    double zeta;
    if (std::scanf("%lf", &zeta) != 1) zeta = 0.12;
    double peak = 0;
    for (double x : simulate<600>(zeta, 2.4))
        peak = x < peak ? x : peak;
    std::printf("zeta = %.2f -> first overshoot: %.4f\\n", zeta, peak);
}`} />

JavaScript runs in a sandboxed worker, instantly and offline — here checking the
integrator against the closed-form solution:

<Code lang="js" runnable code={`const zeta = 0.12, omega = 2.4, dt = 1e-4, T = 3;
let x = 1, v = 0;
for (let t = 0; t < T; t += dt) {
  v -= (2 * zeta * omega * v + omega * omega * x) * dt;
  x += v * dt;
}
const wd = omega * Math.sqrt(1 - zeta * zeta);
const exact = Math.exp(-zeta * omega * T) *
  (Math.cos(wd * T) + (zeta * omega / wd) * Math.sin(wd * T));
console.log("simulated", x.toFixed(6));
console.log("exact    ", exact.toFixed(6));`} />

TypeScript is type-stripped in the worker before it runs — the discriminated union
below is checked by the editor and erased by the runtime:

<Code lang="ts" runnable code={`type Regime =
  | { kind: "underdamped"; ringsAt: number }
  | { kind: "critical" }
  | { kind: "overdamped"; slowPole: number };

function classify(zeta: number, omega: number): Regime {
  if (zeta < 1)
    return { kind: "underdamped", ringsAt: omega * Math.sqrt(1 - zeta * zeta) };
  if (zeta === 1) return { kind: "critical" };
  return { kind: "overdamped", slowPole: -omega * (zeta - Math.sqrt(zeta * zeta - 1)) };
}

console.log(classify(0.12, 2.4));
console.log(classify(2.0, 2.4));`} />

And WebAssembly text is assembled by wabt and instantiated directly — the raw
stack machine, <Marginal note="2ζω = 0.576 and ω² = 5.76 — the constants folded by hand, the way the compilers above fold them for you.">constants folded by hand</Marginal>:

<Code lang="wat" runnable code={`(module
  (import "env" "print_f64" (func $print (param f64)))
  (func (export "main")
    (local $x f64) (local $v f64) (local $i i32)
    (local.set $x (f64.const 1))
    (loop $steps
      (local.set $v (f64.sub (local.get $v)
        (f64.mul (f64.add (f64.mul (f64.const 0.576) (local.get $v))
                          (f64.mul (f64.const 5.76) (local.get $x)))
                 (f64.const 0.05))))
      (local.set $x (f64.add (local.get $x)
        (f64.mul (local.get $v) (f64.const 0.05))))
      (local.set $i (i32.add (local.get $i) (i32.const 1)))
      (br_if $steps (i32.lt_s (local.get $i) (i32.const 100))))
    (call $print (local.get $x))))`} />

## Quiet blocks

Languages the runners don't reach render as the same editor, read-only and
chrome-free — a corner watermark instead of a header:

<Code lang="rust" code={`#[derive(Clone, Copy)]
struct State { x: f64, v: f64 }

fn step(s: State, zeta: f64, omega: f64, dt: f64) -> State {
    let a = -(2.0 * zeta * omega * s.v + omega * omega * s.x);
    State { x: s.x + s.v * dt, v: s.v + a * dt }
}`} />

What rides on all of it from here: scroll-linked figure sequences, richer plates,
and posts whose interactive parts earn their place the way this page's do — the
figure is the argument, the code is the proof, and the annotations are the
conversation in the margins.
