Building the stochastic chemistry simulators at the Gingrich Group, we hit a hard
ceiling with single-threaded execution. Restructuring the update kernels for SIMD
and migrating the hot loop to a [[gpu]]GPU compute pipeline[[/]] cut
wall-clock time by **80%** across a parameter sweep of $10^8$ concurrent
timesteps.<Sidenote n="1">A "timestep" here is one Euler–Maruyama update of the full reaction field — cheap individually, brutal at $10^8$.</Sidenote>

The dynamics we model are the chemical master equation, reduced to a
reaction–rate form:

$$
\frac{d[A]}{dt} = -k_1[A][B] + k_2[C]
$$

The bottleneck was never arithmetic — it was *memory layout*. A naive
[[aos|One struct per particle: a particle's fields sit together, so a vector load straddles particles and must gather.]]array-of-structures[[/]] forces a gather on every lane; a
[[soa|Each field in its own contiguous array, so a single aligned SIMD load fills a whole register.]]structure-of-arrays[[/]] makes the same loop trivially vectorizable.
Hover either term — or the lane width $\htmlData{xref=soa}{w}$ in a packed load $[A]_{i\,\ldots\,i+w}$ — to light it up in the figure.

## The core kernel

In Rust, the SoA kernel is a flat, branch-light loop — exactly what the
autovectorizer wants.<Sidenote n="2">Rust can't be compiled in your browser without a server, so this listing is read-only. The C and WebAssembly blocks below genuinely compile client-side.</Sidenote>

<CodeBlock language="rust" grammar="rust" label="Rust" n={1} code={`pub fn compute_rates(state: &[f32], rates: &mut [f32], k1: f32) {
    // SoA: one contiguous lane, no gather
    for (r, &s) in rates.iter_mut().zip(state) {
        *r = if s >= 0.0 { k1 * s * (1.0 - s) } else { 0.0 };
    }
}`} />

## Run it yourself

The same logistic step in **C**, compiled to WebAssembly *in your browser* and run
off the main thread. Edit it and press run.

<CodeBlock language="c" label="C" runnable n={2} code={`#include <stdio.h>

int main(void) {
    float s = 0.02f, k = 3.9f;
    for (int t = 0; t < 8; t++) {
        s = k * s * (1.0f - s);          // logistic map — a 1-cell reaction
        printf("t=%d  s=%.4f\\n", t, s);
    }
    return 0;
}`} />

You can go a level lower. Here is a hand-written **WebAssembly** module that prints
the first integers — assembled and executed live.

<CodeBlock language="wat" label="WebAssembly" runnable n={3} code={`(module
  (import "env" "print" (func $print (param i32)))
  (func (export "main")
    (local $i i32)
    (loop $l
      (call $print (local.get $i))
      (local.set $i (i32.add (local.get $i) (i32.const 1)))
      (br_if $l (i32.lt_s (local.get $i) (i32.const 6))))))`} />
